# إعداد وتشخيص مزوّدات الذكاء الاصطناعي في JobFinder

## مسارات التشغيل

- **المسار الأساسي للمهام عالية الاستدلال:** عند وجود `OPENAI_API_KEY`، يستخدم JobFinder واجهة OpenAI Responses API لتحليل الإعلان كاملاً واستخراج الوظائف ومراجعة قرارات `APPLY`. النموذج الافتراضي للتحليل هو `gpt-6.1-sol`، ويمكن تغييره عبر `OPENAI_MODEL`.
- **المراجع المستقل لقرارات APPLY:** عند وجود مفتاح OpenAI، تختار Workflows النموذج `gpt-6-astra` افتراضياً ما لم تضبط `OPENAI_REVIEW_MODEL` بنفسك. يعمل هذا النموذج فقط على القرارات المقترحة `APPLY`، وليس على كل إعلان. ويمكن اختيار `gpt-6.1-sol` للمراجعة لتقليل التكلفة.
- **الاحتياط عند غياب OpenAI أو تعذّر استجابته:** Gemini أولاً، ثم نماذج Groq، ثم OpenRouter Free. يبقى كل مسار احتياطي مستقلاً؛ فنجاح Groq مثلاً لا يثبت أن Gemini أو OpenAI استجابا.
- **المهام المساعدة منخفضة الاستدلال:** تستخدم Gemini ثم Groq ثم OpenRouter بحسب ما هو مضبوط. لا تستخدم OpenAI لهذه المهام إلا عندما يكون OpenAI هو المزود الوحيد المهيأ.
- **OpenAI-only مدعوم:** يمكن تشغيل المراقب بمفتاح OpenAI وحده؛ لم يعد فحص بدء التشغيل يشترط Gemini أو Groq.
- يجب أن تتوفر الحصة وصلاحيات API لدى المزود. وجود المفتاح في GitHub Secrets لا يثبت أن الاتصال أو الحصة صالحان في اللحظة الحالية.
- ملاحظة فوترة: اشتراك ChatGPT لا يتضمن رصيد API؛ فوترة OpenAI API منفصلة عن ChatGPT.

## جودة التحليل والتحقق المستقل

- تحليل الإعلان الكامل واستخراج كل وظيفة يستخدمان مستوى reasoning مرتفعاً وميزانية إخراج تسمح بإرجاع JSON للإعلانات متعددة الوظائف.
- عندما يقترح النموذج `APPLY` لوظيفة، يراجع نموذج AI النتيجة بصورة مستقلة، مع ملف المرشح ونص المنصب المحدد وقواعد الأهلية.
- لا يستطيع المراجع ترقية `REVIEW` أو `REJECT` إلى `APPLY`. يُحافظ على `APPLY` فقط عند وجود مراجعة متطابقة للمسمى واقتباس مصدر يمكن التحقق منه؛ غياب المراجعة أو اختلاف المسمى أو غياب الدليل يفرض `REVIEW`.
- تعمل طبقة الملاءمة والموقع ونطاق البريد والحواجز الحتمية بعد ذلك كما هي؛ المراجعة المستقلة لا تتجاوز هذه الحواجز.
- استخدام Astra يضيف استدلالاً أقوى في مراجعات APPLY، لكنه أعلى كلفة وزمن استجابة من Sol. هذا تحسين في جودة التحقق، وليس ضماناً لصحة 100%، ولا يدرّب أوزان النموذج.

## إعدادات GitHub

من **Repository → Settings → Secrets and variables → Actions**:

| الاسم | النوع | الغرض |
|---|---|---|
| `OPENAI_API_KEY` | Secret، اختياري | استخدام OpenAI API للتحليل عالي الاستدلال والمراجعة المستقلة |
| `OPENAI_MODEL` | Variable، اختياري | النموذج الأساسي؛ الافتراضي `gpt-6.1-sol` |
| `OPENAI_REVIEW_MODEL` | Variable، اختياري | الافتراضي `gpt-6-astra` عند ضبط مفتاح OpenAI؛ يمكن تغييره إلى `gpt-6.1-sol` لتقليل التكلفة |
| `GEMINI_API_KEY` | Secret | الوصول إلى Gemini API |
| `GROQ_API_KEY` | Secret | مسار احتياطي مستقل |
| `OPENROUTER_API_KEY` | Secret، اختياري | مسار ثالث مجاني عند تعطل Gemini وGroq |
| `OPENROUTER_MODEL` | Variable، اختياري | الافتراضي `openrouter/free`؛ يقبل فقط هذا المسار أو معرّف نموذج ينتهي بـ `:free` |
| `GEMINI_MODEL` | Variable، اختياري | تغيير نموذج Gemini الأساسي |
| `GEMINI_FALLBACK_MODELS` | Variable، اختياري | قائمة مفصولة بفواصل للنماذج الاحتياطية |
| `JOBFINDER_AI_MIN_REQUEST_INTERVAL_SECONDS` | Variable، اختياري | الحد الأدنى للفاصل بين طلبات كل مزوّد؛ القيمة الافتراضية 3 ثوانٍ |
| `JOBFINDER_AI_OUTAGE_RETRY_SECONDS` | Variable، اختياري | مدة انتظار تعطل المزوّدات مؤقتًا؛ القيمة الافتراضية 300 ثانية |
| `JOBFINDER_AI_CONFIG_RETRY_SECONDS` | Variable، اختياري | مدة إيقاف المحاولات بعد رفض المفتاح/الصلاحيات؛ القيمة الافتراضية 900 ثانية |

اترك متغيّر الفاصل غير مضبوط للاستفادة من القيمة الافتراضية. يمكن تخصيصه عند وجود قياسات فعلية؛ تقليل الفاصل يزيد سرعة المعالجة لكنه قد يزيد أخطاء حدود الاستخدام.

**لا تضع مفاتيح API في الكود أو المحادثة أو سجلّات GitHub.** وجود المفتاح كـ Secret لا يضمن أن حصته متاحة أو أن الخدمة غير مزدحمة.

## لماذا يصل Gemini إلى حدود الاستخدام؟

تختلف الحدود بحسب النموذج ومستوى الاستخدام، وتشمل عادةً عدد الطلبات في الدقيقة، والرموز في الدقيقة، والطلبات في اليوم. وتُطبّق حدود Gemini على مستوى المشروع لا على مستوى مفتاح API؛ إنشاء مفتاح آخر داخل المشروع نفسه لا يضيف حصة مستقلة. راجع الحدود الحقيقية للمشروع في [Google AI Studio — حدود المعدل](https://ai.google.dev/gemini-api/docs/rate-limits).

أما Groq، فتوجد له أيضًا حدود طلبات ورموز، وقد تختلف بحسب النموذج والخطة؛ راجع [توثيق حدود Groq](https://console.groq.com/docs/rate-limits).

### المسار الثالث المجاني: OpenRouter

يستخدم JobFinder `openrouter/free` بعد تعذر Gemini وGroq فقط. يختار OpenRouter نموذجًا مجانيًا متوافقًا؛ لذلك قد يختلف النموذج الفعلي بين الطلبات. وفق [صفحة الأسعار](https://openrouter.ai/pricing)، الحساب المجاني يملك حاليًا حدًا قدره 50 طلبًا يوميًا لنماذج Free (وقد تختلف الحدود بحسب حالة الحساب). لذلك هذا خط إنقاذ أخير وليس بديلًا مضمونًا للحصة الأساسية.

**حماية من التكاليف غير المقصودة:** يمنع الكود النماذج المدفوعة؛ لا يقبل `OPENROUTER_MODEL` إلا `openrouter/free` أو معرّفًا ينتهي بـ `:free`. تُوقف المحاولات إلى OpenRouter لبقية تشغيل المراقب بعد خطأ حصة أو مصادقة أو تعطل مؤقت، لتفادي استنزاف الحد المجاني بمحاولات متكررة.

يخفّض التبديل بين النماذج ذات المسارات المختلفة، والفاصل الزمني، وحفظ حالة إعادة المحاولة من تكرار الفشل، لكنه لا يزيل ازدحام الخدمة أو الحصة اليومية. إذا تكرر بلوغ الحدود أثناء الاستخدام العادي، فتحقق من قيود المشروع والفوترة أو اطلب رفع الحدود بدل تدوير مفاتيح متعددة تشترك في الحصة نفسها.

- `JOBFINDER_AI_OUTAGE_RETRY_SECONDS` (اختياري): مدة تأجيل إعادة المحاولة عند عودة انقطاع/ضغط مؤقت من جميع مسارات Groq، افتراضيًا 300 ثانية، ويُحصر بين 60 و3600 ثانية.

عند استنفاد جميع مسارات Groq، يتعامل البوت الآن مع مزيج من أخطاء 429 وأخطاء 5xx على أنه نفاد فعلي للمسارات المتاحة، وليس فقط الحالة التي تكون فيها كل الاستجابات 429. إذا كانت كل المسارات متعطلة مؤقتًا دون أخطاء حصص، يستخدم قاطع الدائرة فترة انتظار قصيرة بدل تكرار الفشل على كل منشور.

## متابعة حالة المزوّد داخل Telegram

أمر `/status` يعرض الآن آخر مسار نجح فعليًا:
- `OpenAI`: نموذج التحليل عالي الاستدلال ردّ بنجاح.
- `Gemini`: النموذج الأساسي ردّ بنجاح.
- `نموذج Gemini احتياطي`: النموذج الأساسي تعذّر، لكن أحد نماذج Gemini الاحتياطية نجح.
- `Groq البديل`: تعذّر مسار Gemini وعاد التحليل عبر Groq.
- `Groq فقط`: لا يوجد مفتاح OpenAI أو Gemini مضبوط في بيئة التشغيل.
- `OpenRouter`: استُخدم المسار المجاني بعد تعذر المزوّدات السابقة، أو بوصفه المسار الوحيد المهيأ.

يرسل البوت تنبيهًا واحدًا عند الانتقال إلى المسار الاحتياطي، ولا يكرر التنبيه في كل طلب. وعندما يعود Gemini للعمل في تشغيل لاحق، يرسل تنبيه تعافٍ. وإذا تعطلت جميع المسارات، تبقى رسالة فترة الانتظار المحفوظة هي الحالة الأهم.

## اختبار الاتصال دون إرسال طلبات توظيف

من **GitHub → Actions → JobFinder AI Provider Smoke Test → Run workflow** شغّل اختبار الاتصال عند الحاجة.

- يستخدم الاختبار طلب JSON تجريبيًا فقط، ولا يرسل بريد توظيف ولا يغيّر حالة الوظائف.
- إذا نجح OpenAI، ستظهر رسالة نجاح تشير إلى النموذج المستخدم.
- إذا نجح Gemini، ستظهر رسالة نجاح تشير إلى نموذج Gemini المستخدم.
- إذا نجح Groq وحده، فسيظهر أن المسار الاحتياطي هو الذي أجاب؛ لا تعتبر هذه النتيجة دليلًا على أن Gemini سليم.
- إذا نجح OpenRouter، فستظهر رسالة نجاح صريحة لهذا المسار؛ هذا يثبت أنه أجاب عن طلب الاختبار فقط، ولا يثبت صلاحية Gemini أو Groq.
- إذا فشلت جميع المسارات بسبب الحصة، يُظهر الاختبار حالة التعطل ومدة الانتظار المحسوبة.

يُنفّذ اختبار الاتصال ضمن قفل التشغيل نفسه لتجنب منافسة المراقب الحي على الحصة.

## التدقيق للـ 48 ساعة

التدقيق للقراءة فقط لا يرسل رسائل توظيف ولا يحفظ مؤشرات المعالجة، لكنه **يستهلك طلبات AI حقيقية**. لذلك أصبح تشغيله يدويًا، وحجم العينة الافتراضي 12 منشورًا. يمكن اختيار 6 أو 12 أو 20 أو 40 من مدخلات سير العمل. استخدم عينة أكبر فقط عند الحاجة إلى فحص أوسع، لأن ذلك قد يستهلك الحصة المتاحة للمزوّد.
